01

Overview

An official Comfy plugin for Unreal Engine. Artists run ComfyUI workflows from a panel that looks and feels like ComfyUI, on their own GPU or on Comfy Cloud, and get real Unreal assets back: textures and materials, sounds, meshes.

Comfy for Unreal is two pieces that work as one product. Comfy Studio is a tab inside the Unreal Editor with two views: Run, laid out like ComfyUI's App mode, and Graph, the ComfyUI frontend itself. The Comfy for Unreal extension lives inside ComfyUI and lets a workflow author mark which inputs Unreal may change and what each output becomes in the project, the way NVIDIA's RTX Remix tags workflows for its toolkit.

Everything Studio does is also available to Blueprints, Python and AI agents through Epic's Unreal MCP server, so the same workflow can be run by a person, a script or an agent.

Design pillars

Feels like Comfy

Comfy's palette, type and App mode layout, not an Unreal details panel. Anyone who knows ComfyUI is at home.

Assets, not files

Results land as Unreal assets with the right import settings and a record of how they were made.

One workflow, any backend

The same workflow runs on Comfy Desktop, a local install, Comfy Cloud or an API deployment. Model choices adapt to what each backend has.

Authored in ComfyUI

Workflows are built in ComfyUI and tagged there. Unreal never edits graphs; it runs them.

Never surprising

No silent credit spend, no keys in project files, nothing replaced in a level that can't be reverted.

Why now

Epic's 2026 AI MegaJam starts on November 12. UE 5.8 ships Epic's own MCP server with a toolset registry, so agents already live inside the editor. Comfy Cloud removes the GPU barrier for jam teams on laptops. And RTX Remix 1.6.1 (October 23) just showed the pattern in a shipped game tool: ComfyUI as the engine, tagged workflows as the contract.

04

The user experience

Seven journeys, from first launch to an agent doing the work. Each lists what the user does, what they see, and where today's build falls short.

Chips mark the state of each journey: built works in the current build, partial works with gaps, to build is designed here but not built.

1. First run: from install to a connected backend built

Anyone, once per machine. Goal: under two minutes from enabling the plugin to "Connected".
  1. Install and enable. From Fab (later) or a GitHub release now. Enabling pulls in Epic's ToolsetRegistry and Python plugins.
  2. Find it. A Comfy button with the Comfy logo sits in the level toolbar, and Tools › Comfy Studio opens the same tab.
  3. Connect. Studio looks for a ComfyUI it can reach, in this order: the configured address, the ports in Comfy Desktop's installations list, then 8000 (Desktop's default) and 8188 (a manual install). The first that answers /system_stats wins, and the status line turns green: Connected · 127.0.0.1:8000 · ComfyUI 0.39.0, RTX 4080, 14.7 GB free.
  4. No local ComfyUI? The Run view opens on a welcome card that says why, from what Comfy Desktop has installed: not installed, installed with only Comfy Cloud, or installed but not running. It offers Use Comfy Cloud, Get Comfy Desktop and Connect to a URL…. Retry stays in the status line.
  5. Sign in to Comfy Cloud. On Cloud with no key, the card is Sign in to Comfy Cloud. Sign in opens Comfy's own sign-in (Google, GitHub or email) in the Graph view. When it finishes, the status line reads Connected · Signed in as Joshua Jones · 1,751 credits (or 5 of 5 free runs left), and Run works with no key. See Signing in to Comfy Cloud.
  6. Land on the library. With no workflow chosen, the main area shows workflow cards grouped by type, so the first click is "what do I want to make?".
Today: built and tested on October 25. On the test PC, Comfy Desktop has only a Cloud install, and the card says exactly that. Signing in from the card ran a texture on Cloud with no key. Gaps: Launch Comfy Desktop from the card, and a first-run hint for the Graph view.

2. Make a material from a prompt built

Environment artist. Goal: a tileable PBR material on the selected wall in under a minute, without touching ComfyUI.
  1. Pick a workflow. Click the Seamless Texture card, or use the picker at the top of the left column.
  2. Describe the surface. The prompt box is the biggest thing on screen: mossy cobblestone path. Seed is on Randomize, model dropdowns already hold the best match the backend has.
  3. Run. The big blue button at the bottom, with a batch count beside it. Each run appears in the result strip with a progress bar; the status line counts running jobs.
  4. Look. The finished texture fills the preview. Click other results in the strip to compare.
  5. Use it. Replace on selection builds T_…_D, a derived T_…_N and an MI_…, and puts the material on every mesh slot of the selected actors. Revert puts the old materials back and keeps the assets. Ctrl+Z works too.
  6. Come back to it. Project runs, at the bottom of the left column, lists this project's runs newest first, with a thumbnail and when each ran. Hover one to see its inputs. Open it to see the result again, with its workflow and inputs back in the form, ready to run again or change.
Today: built and tested on Comfy Cloud on October 25, through the sign-in: mossy dark cobblestone path and a Brooklyn-inspired red brick wall with vines, each imported as a texture, a derived normal map and a material. Credits in the status line went from 1,751 to 1,749. Import is automatic by default; turn it off under "In Unreal" to only import what you keep.

3. Start from what's in the level built

Artist restyling existing content. Goal: use a texture, mesh or the viewport as the input without exporting anything by hand.
  1. Pick a workflow with an image input. For example, Image to Mesh or a restyle workflow.
  2. Fill the drop zone. There are four ways: drag a texture from the Content Browser, drag a file from Explorer, press Use selection, or press Viewport to capture the active view.
  3. Run. Studio writes textures to Saved/Comfy/Inputs as PNG and uploads them; meshes and sounds go as the file they were imported from.
Today: built. Viewport capture is the beauty pass only; depth and normal passes for ControlNet-style workflows are on the roadmap.

4. Author a workflow for the team partial

Technical artist. Goal: turn a ComfyUI graph into a one-screen form the whole team can use, with outputs that import correctly.
  1. Build the graph in ComfyUI. Use Studio's Graph view (the real ComfyUI frontend, inside Unreal) or in Comfy Desktop.
  2. Expose inputs. Right-click a node › Comfy for Unreal › Expose input to Unreal. Pick the widget, give it a label and say where the value comes from: the form, the main prompt, selected textures or meshes, or a viewport capture.
  3. Tag outputs. On a save node, Tag output for Unreal: a Texture with its slot (Base Color, Normal, Roughness, Metallic, AO, Height, ORM, Emissive, Opacity), or an Image, Sound, Music or Mesh. Tagged nodes show a small UE badge.
  4. Send to Unreal. The action bar button opens a dialog: name, type, description, group and a thumbnail from the last result. The workflow is saved on the ComfyUI server and, inside Studio, lands as a Comfy Workflow asset in /Game/Comfy/Workflows.
  5. Share it. The asset goes into source control with the project. Teammates connected to the same ComfyUI also see it under Server in the picker.
Today: Graph view and Send to Unreal are built and tested; Jones sent a 18-input texture workflow and ran it. The extension (tagging, dialog, sidebar, library) is built but has never loaded: it was only linked into an unused portable ComfyUI, and Comfy Cloud can't load it. It's now linked into Comfy Desktop's install and loads on the next restart there. See Installing the extension.

5. Switch between my GPU and the cloud built

Anyone. Goal: the same workflow runs locally or on Comfy Cloud without editing it.
  1. Pick a backend. The picker is in the status line: Desktop, Comfy Cloud, or a deployment the studio set up.
  2. Studio checks it. The dot shows Connecting, then Connected or Failed with the reason (no key, out of credits, unreachable).
  3. Model dropdowns refill. They read that backend's model list, and each picks the workflow's preferred file again. A workflow that wants flux_vae never silently gets a 4-channel VAE that happens to be named ae.safetensors.
  4. Credits are visible. On Cloud the status line shows the account's free runs or credits, read again a few seconds after every run. to build The cost of a run before you press Run.
Today: switching is built. On Cloud, Run and the model list use the Graph view's sign-in when there's no API key, or when the key is refused.

6. Let an agent do it built

A developer driving the editor through Unreal MCP. Goal: one call from intent to assigned asset, with consent before spending.
  1. The agent discovers the toolset. list_toolsets shows ComfyAgent.ComfyToolset with 18 tools.
  2. One call. GenerateMaterial(prompt: "weathered red brick", bAssignToSelection: true) runs a texture workflow, waits, builds the material and assigns it.
  3. Consent. If the run spends credits, the tool refuses with a message telling the agent to ask the user, then retry with bAllowCreditSpend.
  4. Show the user. OpenStudio("Run") brings the panel up with the result in the gallery.

Graph view

The active backend's ComfyUI frontend in Unreal's embedded browser (Chromium 128 through CEF): the local server's address, or cloud.comfy.org for Comfy Cloud. Sign-ins persist in Saved/Comfy/Browser, and sign-in popups open in their own window so Google and GitHub logins work.

Installing the extension

The extension is a folder in ComfyUI's custom_nodes. ComfyUI reads that folder only at startup, and only on a ComfyUI that loads custom nodes.

WhereStateWhat it takes
Our PC, Comfy Desktoplinked, not loadedLinked October 25 into <install path>\ComfyUI\custom_nodes; the install path comes from Comfy Desktop's installations.json. Before that, the only link was in a portable ComfyUI that hadn't run since, so the extension never loaded anywhere. It loads when the local ComfyUI restarts in Comfy Desktop. Check: GET /comfy_unreal/status answers, the startup log lists comfy-for-unreal under "Import times", and Send to Unreal and the Unreal sidebar tab appear.
Testers, Comfy Desktop or a local ComfyUIproposedShip the extension inside the plugin (Resources/ComfyExtension, keeping its GPL-3.0 license as a separate work). Studio shows it as loaded once /comfy_unreal/status answers. About a day. The Comfy Registry or a ComfyUI Manager git URL comes later; both need a public repository.
Comfy CloudproposedCloud loads no custom nodes, by design, so the extension can't be installed there. Studio already injects a bridge script into the Cloud page; it would also inject the extension's frontend, bundled into one script that uses the page's window.comfyAPI instead of ES imports. Send to Unreal would go straight to Unreal, and the library, which has no server routes on Cloud, would live on the Unreal side or in Cloud's user data. One to two days. This is alpha item 5.

Workflows and the manifest

A Comfy Workflow asset is the API graph plus a manifest. The manifest drives the Studio form, the Blueprint node's pins and the agent schema (see section 9).

The manifest lives in workflow.extra.comfy_unreal and is specified in docs/MANIFEST.md in both repositories. Precedence when a graph comes in: the manifest, then ComfyUI App mode's chosen inputs (extra.linearData), then the plugin's own detection.

The form comes from the workflow

Nothing in the Run view's form is fixed except the "In Unreal" card and the Run bar. Each input card comes from the chosen workflow, in one of two ways:

  1. From the manifest. Built-ins and workflows sent with the extension list their inputs: label, type, node, widget, tooltip, prefer list. The Cloud texture's Surface card is node 10's string_b, renamed by its manifest.
  2. Detected from an Export (API) file. Load Image, Audio and Video nodes become drop zones; Save and Preview nodes become outputs. Widgets with well-known names become cards: text and prompt fields, seed, steps, cfg, denoise, width, height, batch size, seconds, duration, length, and the checkpoint, UNet and LoRA loaders as model dropdowns. A node's title becomes the card's label, so titling nodes in ComfyUI gives a cleaner form.

Detection uses a fixed list of names. Widgets outside it, such as sampler_name, scheduler, guidance or a custom node's own fields, stay as saved in the graph. To put them in the form, expose them with the extension. The canvas save format is refused with a message that asks for Export (API).

Model inputs that travel

Model files differ between machines and Cloud. A Model input lists what the connected backend has and picks the first match from the workflow's prefer list (exact name first, then substring). That fixed a real failure on the test PC, where ae.safetensors turned out to be an SDXL VAE.

When the backend has none of the preferred files, Studio no longer falls back to the first file in the folder, which ran an unrelated model and failed late with a confusing error. The manifest's optional download block (file, folder, size, url) feeds a plain message and a Download button instead, and the run stops before anything is sent. Workflows without a prefer list keep the old behaviour.

Backends

Named profiles in Project Settings, one active per user. Keys never live in project config.

API keys are read from the profile's environment variable (COMFY_API_KEY), then COMFY_CLOUD_API_KEY (comfy-cli's), then the session, then Editor Preferences. Cloud and Router use Authorization: Bearer, the same as Comfy's own SDK. A key the server refuses (401 or 403) is remembered by its hash and skipped until it changes; Cloud then runs with the sign-in.

Signing in to Comfy Cloud

The first Cloud test showed a gap. With no key, the Graph view opened Comfy's sign-in. After sign-in the page was ready to run, with 5 free runs, but Run in Studio still refused because it only knew about API keys. Users should not have to sign in and also make a key.

Built and tested on October 25. Studio injects a small bridge script, Resources/Bridge/comfy_unreal_page.js, after every page load. It reports the account to Unreal and runs Unreal's calls with the page's own sign-in: objectInfo, upload, queue, status (the jobs API), fetch and cancel. In Unreal, FComfyPageBackend is a normal backend that sends those calls through the page, so jobs, progress, downloads and import work exactly as with a key. Two textures ran this way with no key.

The account in the status line. The bridge reads the signed-in user from the frontend's account store, free runs from /api/features (free_tier_balance), and credits from /billing/balance, falling back to the account's own balance on older billing. Both report US cents, even in the fields named *_micros; credits are cents ÷ 100 × 211, rounded as Cloud shows them. It reads again after every run, every minute and when the window gets focus.

The design, as proposed: The ComfyUI frontend exposes its API client as window.comfyAPI. Every call it makes, including queuePrompt, goes through api.fetchApi, which carries the page's Cloud session and refreshes it when it expires (fetchWithUnifiedRemint in frontend 1.53). Studio already has a two-way bridge into the page (window.ue.comfyunreal). So for a signed-in Cloud backend, Studio:

  1. keeps the Graph page loaded, even while the Run view is showing;
  2. uploads inputs by calling /upload/image from inside the page;
  3. calls queuePrompt in the page with the API graph and the UI workflow;
  4. listens to the page's progress, executed and execution_error events and forwards them to the job;
  5. fetches each output in the page and hands the bytes to Unreal through the bridge, which imports them as usual.

The session token never leaves the page. Unreal doesn't store it, so there's nothing to leak in project files or logs. Signing out in the page signs Studio out too.

When a key is needed: the walkthrough

Settings › Comfy Cloud shows these steps inline, with buttons rather than instructions:

  1. Open the key page. A button opens platform.comfy.org to the API keys page, inside the same signed-in browser so there's no second login.
  2. Create a key. Name it after the machine, for example "Unreal · studio-pc".
  3. Paste it. Settings has a password field for it. It is stored in the user's Editor Preferences, never in the project. A Test button checks it and shows the account it belongs to.
  4. Or use a variable. For shared or build machines: COMFY_API_KEY, read when the editor starts.

Ask Comfy Cloud first. The page bridge uses the frontend the way a person does, but programmatically. Confirm with the Cloud team that it fits their terms and rate limits, and whether a supported route is coming, for example an OAuth or device-code sign-in that gives Unreal its own token.

Blueprint, Python and agents

Studio is one client of a public API. Everything it does, a script or an agent can do.

  • Blueprint: the async node Run Comfy Workflow with On Progress, On Completed and On Failed pins; Load Texture From Job and Load Sound From Job for runtime use. The node grows a typed pin per workflow input. Details below.
  • Python: unreal.get_engine_subsystem(unreal.ComfySubsystem) and unreal.ComfyEditorLibrary, reflected automatically.
  • Agents: 18 tools in ComfyAgent.ComfyToolset, including ListWorkflows, DescribeWorkflow (inputs as JSON Schema, model choices as enums), RunWorkflow, WaitForJob, GenerateMaterial and OpenStudio. Results are compact JSON.

Blueprint

One custom node, Run Comfy Workflow (UK2Node_RunComfyWorkflow in the ComfyBlueprint module), plus plain UFUNCTIONs on the subsystem, the job, the workflow and three function libraries.

How the node works

  • Pins from the manifest. Set the Workflow pin to an asset and the node adds one pin per input, labelled as in the Run view. Text and String become text pins, Int a whole number, Float a number, Bool a checkbox, Seed a whole number that defaults to -1 (a new seed every run), Enum a dropdown of its choices, Model a dropdown under the advanced arrow, and an image File input a Texture pin. Other File inputs take a path.
  • Defaults aren't sent. A pin left at its default keeps the workflow's own value. An empty (Auto) model pin lets each backend pick the first preferred file it has, so one Blueprint runs on Cloud and Desktop.
  • Model dropdown. On a local ComfyUI it lists the installed files (once Studio has checked the backend). On Comfy Cloud and Router it lists the workflow's preferred files.
  • Palette. The right-click menu has Comfy › Run Comfy Workflow and one Comfy › Workflows › Run <name> per workflow asset, starters and your own imports included. Each entry places the same node with its Workflow pin already set; nothing is generated per workflow, so there's no conversion step and nothing to regenerate.
  • Wired or empty Workflow pin. When the workflow comes from a variable, the node can't know its inputs, so it shows only the Inputs pin, like Spawn Actor from Class. With the pin empty and a Comfy Inputs connected, the node runs the workflow the inputs name.
  • When the workflow changes. Refresh Node remakes the pins; pins that lost their input keep their wires as orphans and the compile says so. Compiling a node whose workflow changed warns until it's refreshed.
  • Compiles to runtime calls. The pins become a chain of Set (Comfy Inputs) calls feeding UComfyRunWorkflowWithInputsAction, so a packaged game only needs ComfyCore.

Comfy Inputs

A Blueprint variable that holds a workflow's inputs, like a saved App mode form. It names its workflow, so its Details panel lists that workflow's inputs as the Run view does: a text box per prompt, number fields, a checkbox, dropdowns for choices and models, and a texture picker for image inputs. A row left empty isn't stored, so the workflow's value applies; the reset arrow clears a row, with undo. With Instance Editable on, each placed actor shows the same form, so a designer can give each actor its own prompt without opening the Blueprint. Connect the variable to the node's Inputs pin and leave Workflow empty.

Names the workflow doesn't have show in red with a Remove button, so a typo is visible before the run fails. Change the workflow and the rows follow; values that don't fit show as unknown names. Inputs left out keep the workflow's value, except seeds, which get a new seed each run.

In the graph, the same struct is built or changed with Set Text, Set Int, Set Float, Set Bool, Set Seed, Set File, Set Texture and Set Asset, each returning the inputs with one value added, so they chain without exec wires; Get Comfy Input and Clear Comfy Input read and remove one, and Get Comfy Input Choices lists a dropdown's choices. To Comfy Inputs (Map) converts a string map, Validate Comfy Inputs checks without running, and the subsystem's Run Workflow With Inputs runs them. Every name must be one of the workflow's inputs and every value must fit its type, or the job fails before anything is sent: Seamless Texture has no input named "promt". Its inputs: prompt, seed, width, height, ...

Textures become files when the run starts: render targets and textures from Load Texture From File or Job work anywhere, and any texture asset works in the editor. A packaged game can't read other textures' pixels back, and says so. In the editor, meshes and sounds send the file they were imported from.

Starters as assets

Open questions

For the UI review and the UX walkthrough.

  1. Auto-import or keep? Should results import automatically (today's default), or only when the user presses Import or Replace? Auto-import fills the Content Browser fast during exploration.
  2. Where does onboarding live? Answered October 25: a welcome card in the Run view, which is where Studio opens.
  3. Cloud sign-in vs. API key. Built and working through the page bridge. Still open: does the Cloud team bless it, or is a supported sign-in for third-party apps coming? The bridge also depends on frontend internals (the account and workspace stores, /billing/balance units), so it needs checking against each Cloud frontend release.
  4. The extension on Cloud. Cloud doesn't load custom nodes. Studio could inject the extension's frontend script (tagging, Send to Unreal) into the Cloud page itself and store the library in Cloud's user data. Is that acceptable, and does Cloud keep extra.comfy_unreal when it saves a workflow?
  5. Graph toolbar. Once the extension is installed, keep Unreal's own Send to Unreal button above the page, or rely on the one inside ComfyUI?
  6. Batch semantics. Batch count runs N jobs with new seeds. Should "selected textures" run one job per selected asset, like RTX Remix?
  7. Preview for sound and mesh. Partly answered October 25: Play/Stop in the gallery, and Open mesh opens the Static Mesh Editor. A waveform and a turntable can come later.
  8. Brand. Logo usage, the product name, and whether the extension is published by Comfy Org on the registry.
  9. Desktop port. Answered October 25: detect both, plus the ports in Comfy Desktop's installations list.
  10. Run history. Kept per user in Saved/. Should a team be able to share it, for example by saving runs beside the workflow asset?
  11. Texture model. FLUX.2 Klein 4B replaces the proven Flux Schnell graph: smaller for Desktop (11.6 GB against 17 GB) and one family for create and restyle. Is its texture quality as good? The first runs decide.
  12. Mesh license. Hunyuan3D 2.0's license excludes the EU, UK and South Korea. Fine for an internal alpha; for the public release, switch to TRELLIS.2 (MIT) or ship the mesh template without a default model?
  13. Blueprint inputs. Answered October 25: typed pins per workflow, with model dropdowns from the installed files on a local ComfyUI and the preferred files on Cloud and Router. Still open: should the audio starters save WAV so they load in game? See Blueprint gaps.
  14. Upstream templates. Would Comfy-Org take a "Game assets" category in the official templates, so Cloud users get these starters natively?
